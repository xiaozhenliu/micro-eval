# Release Evidence - v0.5.1

## Release scope

- Version: `0.5.1` (patch release); source: `dev`; public target: `main`.
- Preserve the managed-Python runtime alias required by Linux Bubblewrap to
  launch a virtual-environment interpreter with its installed packages.
  The alias is mounted read-only only when it resolves to an already permitted
  runtime root; the original venv interpreter argument is retained.
- Make the annotated-tag enqueue regression test independent of global Git
  identity by supplying a test identity for that Git invocation.
- Apply the optional developer-workflow test condition to its `setup-uv` step
  as well, preventing cache cleanup from failing when those tests are absent.
  Existing test commands, cache settings, and failure gates remain intact.

The user-facing change is recorded in [CHANGELOG.md](../../CHANGELOG.md).
This patch introduces no new configuration or run-schema migration beyond
the [v0.5.0 upgrade notes](2026-09-28-v0.5.0-release-evidence.md#upgrade-notes).

| Linux fixed-policy execution | Exit code 0; 5 passed, 0 skipped, in 13.62 seconds |

The Linux execution used a fixed-image aarch64/musl environment with CPython
3.11.15 and uv 0.12.5. Its five cases comprise three real cell tests and two
runtime-mount regressions: venv prefix and package imports, setup/agent/validator
write boundaries, full/none network policy, read-only runtime aliases, and
rejection of unrelated runtime roots. This is real Linux evidence for that
environment; it does not establish success on GitHub's Ubuntu x86_64 runners.

All five selected cases are synchronous. Disabling pytest plugin autoload
produced one unknown-`asyncio_mode` configuration warning; no test was skipped
because of it. The bounded test container was removed after completion.

## Security boundaries and publication

The repair preserves network policy, workspace/output write boundaries, and
argv-only execution. It does not mount the host root or the entire Python
manager parent directory, and it does not add an unsandboxed retry path.
Existing OS-policy limitations remain: host-readable files are not confidential,
and process-group cleanup cannot cover descendants that deliberately detach.
Cloud live-isolation evidence is outside this patch's verification scope.

After the version-specific source gates pass, commit preparation to `dev` and
use `scripts/release-to-main.sh stage dev main` to verify the actual public
candidate. Publish is a separate, explicitly authorized action using that
exact verified SHA. An annotated `v0.5.1` tag requires explicit approval and
must be published atomically with the same `main` commit. This evidence does not
authorize remote publication or replacement of the existing `v0.5.0` tag.
