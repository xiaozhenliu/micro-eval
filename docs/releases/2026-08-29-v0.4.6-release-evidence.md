## Security

- Secrets redaction: final workspace observations and Git diffs pass through
  ArtifactStore redaction and bounded persistence. Release receipts and
  inventories contain no environment dumps, tokens, account identifiers, or
  credential paths.
- Workspace boundary: validation observes the assigned live workspace before
  cleanup; cleanup and persistence remain owned by the normal lifecycle and
  Store Interfaces. Release tooling uses isolated Git worktrees and does not
  alter evaluation workspace behavior.
- Shell interpolation: trusted execution and release subprocesses remain
  argv-only; no `shell=True` or `create_subprocess_shell` path was added.
- Public projection: all tracked paths must be public, private, or generated;
  unknown/conflicting paths, sensitive files, private-key markers, unsafe
  archive entries, and a public remote containing `dev` abort publication.

## Main projection protocol

The release-preparation commit is staged locally after this evidence is
committed. The exact verified candidate/main SHA, source SHA, policy digest,
artifact hashes, and state are stored in the local receipt under the Git common
directory. A commit cannot embed its own resulting SHA, so the verified receipt
is the authoritative non-self-referential projection record.

No project branch or tag has been pushed while preparing this evidence. Remote
publication requires a later, explicit `publish --expected-sha <FULL_SHA>`
authorization. An optional `v0.4.6` annotated tag must be included explicitly
and is pushed atomically with the same verified `main` SHA.

## Known caveats

- The Next.js production build may report the existing Turbopack NFT tracing
  warning from dynamic filesystem access; compilation and type checking remain
  required to complete successfully.
- Abnormal workspace cancellation, timeout, crash, partial persistence, and
  remote-session recovery remain outside the normal-lifecycle issue scope.
- GitHub Release and package-index upload are not performed by the current
  publication command.
