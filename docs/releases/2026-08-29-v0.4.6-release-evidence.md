The first v0.4.6 preflight correctly stopped because version synchronization
updated the shared UI fixture but not its golden copy. The version synchronizer
now updates both files; the second complete preflight passed. The production UI
build reported the existing Turbopack NFT tracing warning and completed
compilation, type checking, and static page generation.

The first clean stage attempt then stopped before moving `main` because the
concrete-path validator treated Next.js `[jobId]` route names as glob syntax.
Only `*` and `?` are glob operators in the projection Module; bracketed Git
paths are now accepted and covered by regression. Local and remote `main`
remained at their previous SHA, and the post-fix full preflight passed with 654
tests.

The next clean stage created candidate `94a73459e82209560af61d011751a7d910d9f74b`
and then stopped during candidate-tree pytest. The release integration fixture
was still reading its generated `AGENTS.md` source from the private `.codex`
tree, which is correctly absent from a public candidate. The fixture now seeds
that private template from the public `AGENTS.md` inside its disposable test
repository, so the public test suite is self-contained while generation remains
covered. Candidate gate failures now print their captured Python, UI-test, or UI
build tail before aborting. Local and remote `main` again remained unchanged,
focused release coverage passed 27 tests, and the complete preflight passed with
654 Python tests and 115 UI tests.

Candidate `590b40ba3a01cec805eafd6b6752af821292dbec` then passed all 654
Python tests but stopped at the candidate UI build: Turbopack correctly rejected
the validation worktree's `node_modules` symlink because it crossed the
configured candidate filesystem root. Candidate validation now materializes the
installed dependency tree inside that root, using copy-on-write clones on macOS
and reflink-aware copies on Linux. Regression coverage rejects a symlinked
candidate dependency tree. Local and remote `main` remained unchanged, the 27
focused release tests passed, and the complete preflight again passed with 654
Python tests and 115 UI tests.

The subsequent clean stage completed the entire public-candidate path: 654
Python tests, UI tests and production build, candidate wheel/sdist build,
archive allowlists, projection verification, and a `verified` local receipt.
The artifact table above records the candidate artifacts; the candidate sdist
differs from the dev-preflight sdist because the public tree uses the generated
release `.gitignore`. The verified receipt remains authoritative for the exact
candidate SHA and artifact hashes.

## Review status

- The normal workspace lifecycle implementation completed its issue acceptance
  checks and external Codex review before commit `c516184`.
- The release flow is verified through the same deep Release Module interface
  used by the command entry point and temporary bare-origin tests.
- Final local candidate SHA review occurs after the clean release-preparation
  commit through `scripts/release-to-main.sh stage dev main`.

## Security

- Secrets redaction: final workspace observations and Git diffs pass through
  ArtifactStore redaction and bounded persistence. Release receipts and
  inventories contain no environment dumps, tokens, account identifiers, or
  credential paths.
- Workspace boundary: validation observes the assigned live workspace before
  cleanup; cleanup and persistence remain owned by the normal lifecycle and
  Store Interfaces. Release tooling uses isolated Git worktrees and does not
  alter evaluation workspace behavior.
- Shell interpolation: trusted execution and release subprocesses remain
  argv-only; no `shell=True` or `create_subprocess_shell` path was added.
- Public projection: all tracked paths must be public, private, or generated;
  unknown/conflicting paths, sensitive files, private-key markers, unsafe
  archive entries, and a public remote containing `dev` abort publication.

## Main projection protocol

The release-preparation commit is staged locally after this evidence is
committed. The exact verified candidate/main SHA, source SHA, policy digest,
artifact hashes, and state are stored in the local receipt under the Git common
directory. A commit cannot embed its own resulting SHA, so the verified receipt
is the authoritative non-self-referential projection record.

No project branch or tag has been pushed while preparing this evidence. Remote
publication requires a later, explicit `publish --expected-sha <FULL_SHA>`
authorization. An optional `v0.4.6` annotated tag must be included explicitly
and is pushed atomically with the same verified `main` SHA.

## Known caveats

- The Next.js production build may report the existing Turbopack NFT tracing
  warning from dynamic filesystem access; compilation and type checking remain
  required to complete successfully.
- Abnormal workspace cancellation, timeout, crash, partial persistence, and
  remote-session recovery remain outside the normal-lifecycle issue scope.
- GitHub Release and package-index upload are not performed by the current
  publication command.
