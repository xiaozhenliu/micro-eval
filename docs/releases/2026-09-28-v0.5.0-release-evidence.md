## Upgrade notes

- Legacy `baseline`/`candidate` configurations remain readable by the loader.
  Before using the basic configuration form, migrate them to `configurations[]`
  through the Advanced editor.
- Historical runs remain readable. Re-evaluation of a run without saved roles
  or an evaluation contract produces a guarded inconclusive result instead of
  borrowing a contract from the current configuration. A new run is required
  for the new automatic comparison contract.
- `decision_threshold` accepts `(0, 1]` or `null`. Previously accepted zero,
  negative, or above-one values must be corrected; `null` does not yield an
  automatic winner. Automatic comparison confidence is intentionally `low`.
- Strict JSON clients must accept the `cancelled` status, nullable comparison
  data, and the added role/contract snapshots before consuming new records.

## Compatibility and security boundaries

- Provider execution now enforces the selected workspace policy for setup,
  single-turn agents, and command validators. Unsupported network allowlists
  and conversations using a non-logical provider are refused before startup.
- macOS Seatbelt and Linux Bubblewrap have real cell-level positive/negative
  evidence from the implementation verification. Version preparation does not
  change those provider sources. Linux evidence is specific to its recorded
  environment, not a guarantee for every container or host configuration.
- E2B and Modal contracts are tested offline against their pinned SDK versions.
  Optional live-cloud isolation tests were not run; offline results do not
  establish a cloud provider's live security properties.
- Cancelling a Team Server job stops new cell dispatch and retains readable partial results;
  already running cells finish under the configured lifecycle. Process-group
  cleanup does not promise control over descendants that deliberately detach.
- Only selected sanitized artifacts are exported. Linked or oversized artifacts
  are refused; complete binary artifacts retain their redaction caveat.
- Team Server remains for a trusted intranet and does not add authentication or
  TLS. Host-header checks are covered locally; cross-machine hostname/DNS
  connectivity has not been verified as part of this release.
- The recorded `guardrails.timeout_s`, `stop_on_cell_error`, and
  `inconclusive_policy` fields do not currently implement a global timeout
  override, stop-on-first-error dispatch, or a non-zero exit for an
  inconclusive verdict. Configure actual execution timeouts on the agent.
- Runtime configuration overrides are unsupported. Do not infer strict
  rejection of every historical or unknown configuration field.
- The UI still requires the documented source checkout and Node dependency
  installation; the Python wheel does not bundle a standalone Next.js app.

## Publication protocol

Run the complete source preflight, commit preparation to `dev`, then use only
`scripts/release-to-main.sh stage dev main`. Stage must test the actual public
candidate, verify its files and generated templates against the fixed source,
prove the post-boundary single-parent public history, and validate both archive
allowlists before moving local `main`. The v2 `verified` receipt is required.

Remote publication is a separate exact-SHA approval and `publish` action.
An annotated `v0.5.0` tag is included only when explicitly approved and then
must be pushed atomically with the same verified `main`. Package-index upload
and a GitHub Release are separate actions and are not part of this command.
