# Development Log - v0.4.5 Release

## Summary

Prepared the v0.4.5 patch release around reproducible command execution and Team Server run-state integrity.

## Context

The post-v0.4.4 example smoke work exposed two follow-ups: command placeholders behaved differently across execution entry points, and a Team Server worker timeout could leave the queue job failed while canonical `run.json` remained running.

## Changes

- Added shared argv-only placeholder resolution for agent, setup, and validation commands.
- Persisted canonical failed run status and a redacted failure reason for worker timeout and execution errors.
- Updated stale-job recovery to preserve failed status, support custom output directories, and reject path escapes.
- Synchronized Python and TypeScript run contracts and regenerated golden fixtures.
- Expanded CI smoke coverage without adding external-service requirements to ordinary CI.

## Decisions

- Placeholder replacement remains per argv element and never invokes a shell.
- `{python}` is common to all executable entry points; path placeholders remain limited to stages where those paths exist.
- Queue and canonical run stores remain separate persistence systems. If canonical failure persistence itself fails, the queue error records that synchronization failure explicitly.

## Verification

- Issue #01 focused verification: 55 Python tests passed.
- Issue #02 focused verification: 49 Python tests and 115 Vitest tests passed.
- Independent Standards and Spec reviews were performed for both implementation slices; blocking findings were addressed before commit.
- Full release preflight and package-build evidence are recorded in the linked release evidence document.

## Risks and follow-ups

- Remote push, annotated tag creation, and remote publication require explicit maintainer approval.
