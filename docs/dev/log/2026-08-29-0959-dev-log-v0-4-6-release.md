# Development Log - v0.4.6 Release

## Summary

Prepared v0.4.6 as a patch release for normal workspace lifecycle correctness
and the verified fail-closed public release flow.

## Context

After v0.4.5, `dev` closed the normal cell finalization ordering bug and added a
white-listed release projection. The source branch also contains substantial
internal analysis, plans, local agent instructions, and historical docs. Those
materials are intentionally private and must not enter the public candidate.

## Changes

- Synchronized current version surfaces from 0.4.5 to 0.4.6.
- Promoted the Unreleased lifecycle and release-safety entries into the v0.4.6
  changelog section.
- Generated human-readable and JSON dependency inventories.
- Added v0.4.6 release evidence with real wheel/sdist hashes and explicit
  public/private projection expectations.
- Extended version synchronization to update both the shared UI fixture and its
  committed golden copy.

## Decisions

- Use a patch release because the public product changes correct lifecycle and
  publication behavior without changing the canonical external schema.
- Keep internal analysis, security reports, dev logs, planning material,
  `.codex`, and local issue state private even though they remain committed on
  local `dev`.
- Treat the local verified receipt as the authoritative projection SHA record;
  release evidence cannot embed the SHA of the commit that contains itself.

## Verification

- The first preflight stopped with 652 passing tests and one golden-idempotence
  failure because the synchronized UI fixture and its golden copy differed.
  `sync-version.py` was fixed to update both surfaces.
- The second full preflight passed: version/evidence consistency, path planning,
  compilation, 653 Python tests, UI lint, 115 UI tests, UI production build,
  wheel/sdist build, archive allowlists, diff checks, and shell safety gates.
- The first clean stage stopped safely because Next.js bracketed route names
  such as `[jobId]` were misclassified as glob syntax. Local and remote `main`
  remained unchanged. The validator now treats only `*` and `?` as supported
  glob operators, and focused release coverage increased to 27 passing tests.
- The post-fix full preflight passed with 654 Python tests and the same 115 UI
  tests, build outputs, artifact hashes, and public/private plan counts.
- The next clean stage created candidate
  `94a73459e82209560af61d011751a7d910d9f74b` and stopped during candidate
  pytest because the release integration fixture still read its sample from
  the intentionally private `.codex` tree. Local and remote `main` remained
  unchanged. The fixture now constructs the private template inside its
  disposable repository from public `AGENTS.md`, and candidate Python/UI/build
  failures print their captured output before aborting.
- After that repair, focused release tests passed 27 checks and another complete
  preflight passed 654 Python tests, 115 UI tests, lint, production build,
  artifact allowlists, and projection policy checks.
- Candidate `590b40ba3a01cec805eafd6b6752af821292dbec` passed all 654
  Python tests, then stopped because Turbopack rejected the candidate
  `node_modules` symlink for crossing its configured filesystem root. Local and
  remote `main` remained unchanged. Candidate validation now materializes the
  installed dependency tree inside the candidate root with copy-on-write or
  reflink-aware copies, and regression coverage rejects the old symlink setup.
- The post-repair focused release suite passed 27 tests and the complete
  preflight again passed 654 Python tests, 115 UI tests, lint, production build,
  artifact allowlists, and projection checks.
- The plan classified 423 public, 88 private, and 2 generated paths. The public
  candidate contains 425 paths.
- The wheel has 73 verified entries and SHA-256
  `53ab93d3b64cc2cf5829593d3187c558da95373f18dee002ab7e64f35ff92ba2`;
  the sdist has 76 verified entries and SHA-256
  `458584ef5185fe6b9b24b8418325fe3568c22049669b4b0ea67e10540ba10800`.
- Local-only stage remains pending until the release-preparation changes are
  committed and the `dev` worktree is clean.

## Risks and follow-ups

- Abnormal lifecycle recovery remains separately scoped.
- No public remote mutation or tag creation is authorized during preparation.
